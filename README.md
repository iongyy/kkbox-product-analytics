# PA-S1 · KKBox Churn — продуктовая аналитика подписки

Учебный проект по дисциплине «Продуктовая аналитика» (МГТУ им. Н.Э. Баумана), трек Б (индивидуальный).
Анализ оттока и юнит-экономики музыкального стриминга KKBox на данных конкурса
[WSDM — KKBox's Churn Prediction Challenge](https://www.kaggle.com/c/kkbox-churn-prediction-challenge/data) (Kaggle, 2017).

## Состав репозитория

- `PA_S1_KKBox.ipynb` — основной ноутбук: продукт, данные, определения, метрики, трекинг, когортный retention, LTV/CAC, этика, критерии успеха
- `requirements.txt` — зафиксированные версии зависимостей
- `data/` — данные (не коммитятся, см. ниже)

## Данные

Данные скачиваются со [страницы конкурса на Kaggle](https://www.kaggle.com/c/kkbox-churn-prediction-challenge/data)
(требуется аккаунт Kaggle и принятие правил конкурса; сырые данные не публикуются — поэтому `data/` в `.gitignore`).

Нужные файлы (окно v1) положить в `data/`:

| Файл | Содержимое | Строк |
|---|---|---|
| `members_v3.csv` | пользователи: город, возраст, пол, канал и дата регистрации | 6,77 млн |
| `transactions_v1.csv` | транзакции: план, цена, оплата, автопродление, отмена, даты | 21,5 млн |
| `user_logs_v1.csv` | дневные логи прослушиваний | ~0,5 млрд (28 ГБ) |
| `train_v1.csv` | метка оттока `is_churn` (нет продления 30 дней после окончания) | 993 тыс. |

`user_logs_v1.csv` для основного прогона не обязателен — расчёты по нему выключены флагом
`RUN_LOGS_SCAN = False` в первой кодовой ячейке.

## Как запустить

```bash
pip install -r requirements.txt
jupyter notebook PA_S1_KKBox.ipynb
```

В ноутбуке: Kernel → Restart & Run All. Полный прогон занимает ~6 минут (без сканирования логов),
требуется ~8 ГБ свободной RAM. Все пути относительные (`data/...`).

## Что получилось (baseline)

- Подписочное удержание (по валидности подписки): M1 = 98,5%, M3 = 86%, плато ~73% к M11
- Платёжное удержание (диагностическое): взвешенный M1 = 66,5%, M3 = 62%
- MAPU (North Star, по валидности подписки): 1,08 млн (2017-02), пик 1,13 млн (2016-09)
- LTV_24 ≈ 598 NTD когортным интегралом (ARPPU 135 NTD, маржа 25% — допущение); LTV/CAC ≥ 3 при CAC ≲ 200 NTD
- Churn на экспирации (риск-метрика): 6,4%
- Ограничение: расходов на привлечение в данных нет — CAC и маржа заданы допущениями
